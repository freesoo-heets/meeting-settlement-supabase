STEP 28 - 리팩토링 및 안정성 점검

이번 패치에서 실제 반영한 항목
1. loadAll 데이터 조립 성능 개선
   - 기존: 모임마다 attendance/guest 전체 배열을 filter
   - 변경: meeting_id 기준 Map을 한 번 생성 후 조립
   - 효과: 모임/참석 데이터가 늘어날수록 불필요한 반복 연산 감소

2. 최근 참석일 계산 개선
   - 기존: 회원마다 전체 모임을 다시 검색하고 날짜 정렬
   - 변경: 전체 모임을 한 번 순회하며 회원별 최신 날짜 갱신
   - 효과: 회원/모임 수가 늘어날 때 렌더링 계산량 감소

3. 중복 상태 초기화 제거
   - setGuestFixedDrafts({})가 연속 2회 호출되던 부분 1회로 정리
   - 효과: 불필요 코드 제거, 유지보수성 향상

4. 사용하지 않는 과거 대시보드 CSS 제거
   - Step 27/27.1 이전 화면용 selector 중 현재 JSX에서 참조되지 않는 항목 제거
   - 효과: CSS 충돌 가능성 및 누적 스타일 복잡도 감소

5. Service Worker 캐시 정책 개선
   - 기존: 동일 도메인의 모든 GET 응답을 캐시
   - 변경: 정적 리소스만 캐시하고 화면 navigation은 network-first
   - 효과: 로그인/동적 화면의 오래된 응답이 캐시로 남는 위험 감소
   - PWA 캐시 v14

점검 후 추가 권장 항목
A. app/page.tsx 컴포넌트 분리
   - 현재 단일 파일이 약 4천 줄
   - Dashboard / Meetings / Members / Monthly / History / Help로 분리 권장
   - 효과: 기능 수정 시 영향 범위 축소, 코드 리뷰/디버깅 쉬움

B. globals.css 기능별 분리 또는 CSS Module 도입
   - 현재 약 3천 줄이며 Step별 스타일이 누적
   - 효과: 과거 스타일과 신규 스타일의 override 충돌 감소

C. 일반회원 쓰기 권한 재검토
   - 기존 RLS는 meetings/attendance/settlement/guest/prepayment를 can_use_app() 사용자에게 all 허용
   - 일반회원이 조회만 해야 한다면 admin/owner만 write 가능하도록 RLS와 UI를 함께 변경 권장
   - 효과: 실수/오조작 및 권한 범위 축소

D. 활동 로그 무결성 강화
   - 현재 클라이언트가 activity_logs를 직접 insert
   - 서버 API 또는 DB trigger/RPC로 기록하면 로그 위변조 가능성을 낮출 수 있음

E. 비밀번호 변경 재인증
   - 현재 로그인 상태에서 새 비밀번호만 입력하면 변경 가능
   - 민감 작업 재인증 또는 최근 로그인 확인을 추가하면 계정 보안 향상

F. 로그인 닉네임 조회의 계정 존재 여부 노출
   - nickname 조회 API 구조상 등록 닉네임 존재 여부를 추측할 수 있음
   - 로그인 응답을 동일화하거나 rate limit 적용 권장

G. 관리자 회원 삭제 트랜잭션성
   - Auth 삭제 후 members 삭제 실패 시 부분 완료 가능
   - 서버 함수/보상 로직 강화 또는 soft-delete 우선 정책 권장
