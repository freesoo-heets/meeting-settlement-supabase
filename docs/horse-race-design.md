# 찐친 경마게임 A안 — 1차 확정 설계 (2026-11-24)

## 목표와 범위
- 기존 게임 메뉴에 추가할 **단체 무료 승부예측형 경마**. 별도 유료 판돈·배당·현금성 환전 없음.
- 로그인한 활동 회원 2~20명, 말 6마리. 회원은 **말 한 마리**만 선택하며 같은 말에 여러 명이 응원 가능.
- 관전은 별도 정원(읽기 전용). 방장도 응원 가능. 중복 참여 금지.
- 운영 DB 변경/보상 집행/메뉴 노출은 **후속 PR**에서 단계적으로 수행.

## 규칙 (초기값, 운영자 설정 가능하도록 설계)
1. 방 만들기: 방장은 친선/포인트 보상 모드 선택. 초기 운영은 친선 모드만 활성화.
2. 입장/선택: 2~20명. 1인 1마리(1~6번), 시작 이전 변경 가능. 시작 이후 변경/입장 불가(관전 가능).
3. 출발: 방장만 시작, 선택 완료한 회원 2명 이상 필요. 5초 카운트다운 동안 선택 잠금.
4. 경기: 6마리가 같은 경기에서 약 19~25초에 결승선 통과. 250ms 간격의 고정 레이스 프레임 사용. 클라이언트 시계가 아니라 서버 시작시각 기준으로 재생.
5. 판정: 서버에만 보관한 무작위 256-bit seed로 한 번 결정. 1~6위 모두 확정. 서버 결과 저장 뒤 모든 클라이언트에 동일 순위 표시. 동점 없음.
6. 보상(후속 단계): 예측한 말의 **최종 순위**로 1위 100점, 2위 50점, 3위 20점, 4~6위 0점. 참가비 0. 별도 친선/테스트는 0점.
7. 보상 한도(후속 단계): 회원별 하루 최대 300점; 기준일은 Asia/Seoul 오전 06:00부터 다음날 05:59. 포인트 경제 및 봇 정책 검토 후 활성화.
8. 점수 입출금은 기존 봇 정산 채널만 사용. 사이트가 bot_points를 직접 변경하지 않음. (race_id, member_id) 멱등 보상 ID 필수.
9. 방장은 출발 전에 취소 가능. 진행 중 취소는 관리자만 사유 기록 후 처리. 보상 미확정 시 미지급으로 보관하여 자동 중복 지급 방지.
10. 재접속 시 같은 레이스 데이터와 결과 복원. 30분 이상 대기 중인 무인 방 정리. 개인 및 전체 기록 열람 제공.
11. 랜덤성: seed는 서버에서 race 시작 시 생성해 비공개 저장. 결과 확정 전 클라이언트로 전송하지 않음. 완료 후 seed/해시 검증 정보 공개 가능.
12. 모든 말은 동일한 확률로 우승할 수 있도록 구성; 속도 변동은 시각 연출이고 결과는 서버에서 확정.

## 화면
- 게임 허브: 🏇 경마 카드, 대기 중 경기 목록, 방 생성 버튼.
- 대기실: 회원명 / 선택말 / 참가인원 / 준비현황 / 출발 버튼(방장).
- 경기: 가로 6레인, 말별 이름·현재 순위, 카운트다운, 경주 애니메이션, 모바일 뷰.
- 결과: 결승 순위 1~6위, 나의 응원말, 참여 회원, 포인트(활성화 시) 및 다시하기.
- 운영자: 테스트 방, 강제 종료, 미지급 점검(후속).

## 충돌 방지 및 검증 게이트
- main과 열린 PR 확인 후 매 단계 rebase/충돌 확인. 특히 GameHub, /game 라우팅, 정산·PET·타로 영역을 덮어쓰지 않는다.
- 테스트: seed 동일성, 서로 다른 seed, 6위 완결, 위치 단조 증가, 27초 도달, 보상 매핑, 동시 시작 한 번만 성공, 지연접속 재생동기화, 로그인/RLS, 모바일.
- 배포 전후 npm run build, 기존 오목/알까기/캐치/홀덤/단어게임 및 포인트/티켓 회귀 테스트.
- 포인트 보상은 검증 전 활성화하지 않고, 운영 환경의 DB 마이그레이션도 별도 승인 후 실행.
